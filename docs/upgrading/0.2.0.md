# Upgrading to 0.2.0

The Worker wiring moved into `@castra-kit/app` ([ADR 0077](../adr/0077-create-castra-app.md)). This is the last
release that needs an edit to `src/index.ts`; later middleware arrives with a package bump.

1. Bump the packages and add the new one:

   ```bash
   pnpm add @castra-kit/app@0.2.0 @castra-kit/core@0.2.0 @castra-kit/auth@0.2.0 @castra-kit/mcp@0.2.0 @castra-kit/cli@0.2.0
   ```

2. Replace the wiring in `src/index.ts` with one call. Keep your own routes in `routes` (they see `c.get("ctx")`) and
   CORS or logging in `before`:

   ```ts
   import { createCastraApp, type CastraBindings } from "@castra-kit/app";
   import type { CastraAuthOptions } from "@castra-kit/auth";
   import type { SchemaSnapshot } from "@castra-kit/core";
   import config from "../castra.config";
   import schema from "../castra/schema.json";

   export type Env = CastraBindings;

   export const authOptions: CastraAuthOptions = { roles: config.roles };

   export default createCastraApp<Env>({
     config,
     snapshot: schema as unknown as SchemaSnapshot,
     auth: authOptions,
     openapi: { title: "My app" },
     // routes: (app) => app.get("/hello", (c) => c.json({ user: c.get("ctx").user })),
   });
   ```

   If you added bindings to `Env`, extend it: `export interface Env extends CastraBindings { MY_KV: KVNamespace }`.

3. Keep the `RATE_LIMITER` entry in `wrangler.jsonc` and add `AUTH_RATE_LIMITER`, the tighter bucket for sign-in and
   sign-up ([rate limiting](../rate-limiting.md)). Without a binding, the Worker logs a warning and that limit is off:

   ```jsonc
   { "name": "AUTH_RATE_LIMITER", "namespace_id": "1002", "simple": { "limit": 10, "period": 60 } }
   ```

4. Run your tests and `pnpm run typecheck`, then `pnpm doctor`: it reports mixed `@castra-kit/*` versions, missing
   rate-limit bindings and schema drift (`pnpm doctor -- --remote` for the deployed database).
