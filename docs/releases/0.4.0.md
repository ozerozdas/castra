# v0.4.0 — Local MCP migrations (Issue #20, ADR 0086)

**Date:** 2026-10-19

This release exposes local-only MCP tools for creating and applying D1 migrations through `castra mcp`.
Remote `/mcp` never registers these tools; the approval gate keeps a human in the loop; and Wrangler stays the runner.

## Highlights

- New `generate_migration` MCP tool creates the next numbered file in `migrations_dir` and previews the comment template.
- New `apply_migration { approve }` MCP tool lists pending migrations and, with explicit approval, runs `wrangler d1 migrations apply` after a successful drift check.
- Tools are registered only when the CLI provides a migrations callback, so existing stdio and all remote `/mcp` servers remain unchanged unless opted in.
- No new audit code: local stdio writes no `_castra_audit` rows today, and remote `/mcp` is not extended.

## Added

- `generate_migration { name }` — local `castra mcp` only. Writes `<migrations_dir>/NNNN_<slug>.sql` with header and rollback comments; returns the path and file body. Never applied.
- `apply_migration { approve }` — local `castra mcp` only. Always runs `migrateStatus`; with `approve: true` it runs the snapshot drift check, then `wrangler d1 migrations apply`, and reports the exit code. Without approval, returns a dry-run summary.

## Changed

- None.

## Migration

- No database migration is required.

## Operator notes

- `castra mcp` now exposes two new tools when the CLI passes a migrations callback (the default CLI behaviour). Clients must opt in by providing a migrations callback; otherwise the tool set is unchanged.
- The CLI wires callbacks from `migrateCreate`, `migrateStatus`, `generate`, and `migrate`, and wraps the wrangler `exec` call so stdout does not enter the MCP stdio stream.

## Security

- Local-only: the tools register only for `castra mcp` stdio; the remote `/mcp` route never sees them.
- Approval gate: `apply_migration` only mutates when `approve: true` is passed explicitly; any other value returns a dry-run summary.
- Wrangler remains the runner: the MCP layer never executes migration SQL itself, preserving the wrangler-managed `d1_migrations` table as the source of truth.

## Upgrade

1. Bump `@castra-kit/*` packages to `0.4.0`.
2. Run `pnpm install`.
3. Restart `castra mcp` to pick up the new tools.

No other action is required; the release does not change the database schema or the remote MCP surface.
