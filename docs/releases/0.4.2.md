# v0.4.2 — Dependency security patch release

**Date:** 2026-11-08

Patch release that closes the open Dependabot alerts. No feature, API, schema or MCP surface change.

## Security

All alerts were in transitive dependencies:

| Package | Alerts | Fixed by |
|---|---|---|
| `undici` 7.x | #13, #15–#18 | `wrangler` 4.158.0 → miniflare → `undici` 7.30.1 |
| `zod` (vitest-plugin) | #3 | `@cloudflare/vitest-plugin` 1.6.0 → `zod` 4.6.6 |
| `undici` 6.x | #10, #12, #19–#21 | override → 6.29.1 (`@readme/openapi-parser`) |
| `fast-uri` | #5–#8 | override → 3.1.9 (`ajv`, via MCP SDK) |
| `body-parser` | #4 | override → 2.4.0 (`express`, via MCP SDK) |
| `ip-address` | #2 | override → 10.7.4 (`express-rate-limit`, via MCP SDK) |
| `qs` | — (`pnpm audit`) | override → 6.16.1 (`express`, via MCP SDK) |

The overrides live in `pnpm-workspace.yaml` and only affect this repo's lockfile. Published packages keep their
normal ranges, so a consumer gets the patched versions from a fresh `pnpm install` or `pnpm update`.

## Changed

- `wrangler` 4.158.0, `@cloudflare/vitest-plugin` 1.6.0, `@cloudflare/workers-types` 5.20261108.1 in the
  workspace and in the `create` template.

## Known, not fixed

- `minimatch` < 11.0.1 (moderate, via `eslint`, dev-only lint tooling). The fix is a major version that `eslint`
  10.x does not accept yet; forcing it could break lint. Revisit when `eslint` moves to `minimatch` 11.
