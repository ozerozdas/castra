# v0.4.3 — Dependency patch release

**Date:** 2026-11-12

Patch release that rolls up the pending dependency updates and fixes the `create` template drift. No feature, API,
schema or MCP surface change.

## Fixed

- The `create` template pinned `better-auth` 1.7.7 while the workspace was on 1.7.12 (now 1.7.22), so a freshly
  scaffolded project installed a second, older `better-auth` next to `@castra-kit/auth`'s. The template now matches
  the workspace, and a test fails when any third-party template dependency drifts from the workspace version.

## Security

- `propose_policy` (local stdio MCP only) scans core imports in linear time. The previous regex was polynomial on
  adversarial input (CodeQL `js/polynomial-redos`); behavior is unchanged.
- The workspace `pnpm.overrides` for `undici`, `fast-uri`, `body-parser`, `ip-address` and `qs` are removed:
  upstream ranges now resolve to the patched versions, so the pins only affected this repo's lockfile. The
  `esbuild` override stays for `tsup`.

## Changed

- Runtime dependencies: `hono` 4.13.18, `better-auth` 1.7.22, `@modelcontextprotocol/sdk` 1.32.2, `kysely` 0.29.8.
  `better-auth` 1.7.22 includes two Cloudflare Workers fixes: verification-value consumption no longer hangs after
  an earlier request for the same identifier ended mid-query, and module-scope auth instances no longer log a schema
  validation error on every cold start. Its generated D1 schema is unchanged, so no auth migration is needed.
- Dev tooling: `eslint` 10.14.0 and `typescript-eslint` 8.72.2 in the workspace; `wrangler` 4.161.0, `vitest` 5.1.0,
  `@cloudflare/vitest-plugin` 1.8.1 and `@cloudflare/workers-types` 5.20261112.1 in the workspace and the `create`
  template.

## Known, not fixed

- `minimatch` < 11.0.1 (moderate, via `eslint`, dev-only lint tooling), unchanged from 0.4.2. The fix is a major
  version that `eslint` 10.x does not accept yet; forcing it could break lint. Revisit when `eslint` moves to
  `minimatch` 11.

## Migration

- No database migration is required.
