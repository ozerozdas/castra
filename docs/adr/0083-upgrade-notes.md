# 0083. Generated upgrade notes and an upgrade test

## Status
Accepted (2026-10-12). Issue #19 (parts 3 and 4). Follows ADR 0077, which moved the Worker wiring into a package.

## Context
A scaffolded project owns its copy of the template. Package bumps carry most changes since ADR 0077, but template
files (`wrangler.jsonc`, `src/index.ts`, scripts, dependencies) still change between releases, and a hand-written
upgrade note drifts from what actually changed. Nothing checked that a note gets a project from one release to the
next.

## Decision
- **One note per release** that changes the template: `docs/upgrading/X.Y.Z.md`, with an
  `<!-- upgrade-from: vPREVIOUS -->` line. Prose (why, manual steps) is written by hand; the "Template changes" section
  between the `template-diff` markers is generated by `scripts/upgrade-note.mjs X.Y.Z --write` from
  `git diff vPREVIOUS vX.Y.Z` (the working tree until the tag exists) over `packages/create-castra/template`.
- **package.json is not diffed.** Dependency changes become `pnpm add` / `pnpm remove` lines (all `@castra-kit/*`
  pinned to the new version), and script changes a JSON block, so they apply to an edited package.json. Other files
  get a unified diff with project paths (`_gitignore` → `.gitignore`), applicable with `git apply`.
- **CI** checks out with tags, fails if a note's section is stale (`--check`), and runs
  `pnpm --filter @castra-kit/create test:upgrade`: scaffold the previous release's template from `git archive`, apply
  the newest note as written (package lines, scripts, `git apply` of the diffs) with the Castra packages linked to the
  checkout, then install, typecheck, test, policy tests, local migrate and `castra generate --check`.

## Consequences
- A template change without a regenerated note fails CI; a note whose diffs do not apply, or leave a project that
  does not build and pass its tests, fails CI.
- Only the newest note is exercised, from a freshly scaffolded project. Projects with edited files merge the diffs by
  hand; the note says so.
- The upgrade test installs third-party packages from the registry, so CI needs network access (it already does).
